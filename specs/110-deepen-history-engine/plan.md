# Implementation Plan: Deepen Historical Engine & Demote Leaky Firestore Storage Layer

**Branch**: `110-deepen-history-engine` | **Date**: 2026-11-15 | **Spec**: [spec.md](./spec.md)

---

## Summary

Deepen `HistoryResolutionEngine` into the authoritative historical coordinator across all asset domains (rates, gold, stocks, indices, and GCC equities) by absorbing multi-day range slicing, flat-cache persistence, and single-source negative caching behind its existing two-method seam (`getDateSnapshot`, `getDateRange`). Concurrently demote `firestore-service.ts` into a pure stateless database adapter, eliminate `src/cache/history-cache-store.ts`, and prune over 300 lines of duplicate range slicing boilerplate from caller query services.

---

## Technical Context

**Language/Version**: TypeScript 5.6 / Node.js 22+ (ESM)  
**Primary Dependencies**: Fastify 5.0, `flat-cache` 6.1, `@google-cloud/firestore` 8.6, `zod` 3.23  
**Storage**: Persistent disk key-value store (`flat-cache` in `var/cache/` with 30-day TTL), in-memory Map caches, Cloud Firestore weekly bucket documents (`{collection}_weekly/{YYYY-Www}`)  
**Testing**: Vitest 4.1 (`npm run test:unit`, `npm run test:contract`), differential verification suite (`npm run verify:diff`)  
**Target Platform**: Oracle Cloud Infrastructure (OCI) Ampere A1 Compute (4 ARM64 cores, 24GB RAM)  
**Project Type**: Fastify RESTful API Gateway  
**Performance Goals**: $<10\text{ ms}$ for cached ranges from `flat-cache`; $<200\text{ ms}$ p95 across all historical queries; zero Firestore reads for sealed dates  
**Constraints**: 100% backward-compatible JSON contracts; 100% test pass rate; zero direct Firestore reads for sealed past weeks; strict code commenting on every line per Constitution Principle V  
**Scale/Scope**: 5 asset domains (`rates`, `gold`, `stocks`, `indices`, `gcc-stocks`), 1,180+ securities, multi-month date ranges
